3 Good Patterns

✅
Typed Cube Data
The Cube dataclass gives the simulation a clear shape for its state and keeps the code easy to reason about.
Basics: Fields like x, y, and vx are declared once, so the object structure is obvious.
Engineering: Type hints reduce mistakes when the cube flows through update, collision, and draw functions.
Architecture: The dataclass acts like a contract for the rest of the simulation.
✅
Separation of Concerns
Neighbor search, steering computation, physics updates, and rendering each live in their own function.
Basics: Each helper does one job instead of mixing logic together.
Engineering: The functions are testable in isolation, which makes debugging much easier.
Architecture: update_cube() becomes a readable pipeline from threats to motion to collision.
✅
Top Level Tuning
Behavior knobs like FLEE_RADIUS, FLEE_STEER, and CUBE_COUNT are centralized near the top of the file.
Basics: The important numbers are easy to find and change.
Engineering: You can tune behavior without editing the core logic.
Architecture: The file has a clean split between configuration and runtime behavior.

2 Potential Issues

⚠️
Quadratic Neighbor Search
Every cube scans the full cube list, so the cost grows quickly as more objects are added.
Basics: The nested loop checks every neighbor against every cube.
Engineering: The current approach is fine at 15 cubes, but it scales poorly.
Architecture: A grid or quadtree would be the next step if the simulation grows.
⚠️
Unused Player Factory
The file defines create_player(), but runtime flow uses only create_cube(), so the player factory currently behaves like dead code.
Basics: The function exists, but no caller uses it in main().
Engineering: Unused paths increase maintenance cost and confuse future refactors.
Architecture: Keep separate factories only if they map to a real game role with clear ownership.

Performance Analysis

Performance Wins

Direct drawing
draw_cube() uses pygame.draw.circle() directly, which keeps rendering simple and cheap.
Small fixed workload
With only 15 cubes, the current frame budget is comfortable on a normal laptop.

Performance Risks

Quadratic neighbor checks
find_bigger_neighbors() compares each cube against the whole list every frame.
Repeated square roots
Distance math is recomputed in the search and steering stages instead of being cached or simplified.
4 / 6 - Fine for a small demo, but a spatial grid would be the next scaling step.
